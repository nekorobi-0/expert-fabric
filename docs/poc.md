# 最小PoC

## 最初に確かめること

単一engine・単一MLP形式で、ネットワーク越しのexpert実行と重みの世代切り替えを成立させる。

1. CPUとローカルファイルでLOAD / PUBLISH / INVOKE / RETIREの意味を実装する。
2. 参照計算との一致、受付済み要求の世代固定、旧世代の排出を確認する。
3. transportを差し替えられる境界を設け、RDMA配送を追加する。
4. 重みの供給元をNFS/RDMAに替えて、ロードと推論の競合を測る。
5. HIPバックエンドを追加し、AMD Instinct MI50とRadeon RX 7900 XTXそれぞれで、ホストRAMからVRAMへの重みの転送と演算を検証する。GPUごとに動作確認したROCm、OS、カーネル、ドライバの組み合わせを記録する。
6. YAMLで複数接続先を設定し、CPU／GPUの実行先リストを取得する。容量で候補を絞り、帯域を使って配置先を選び、メイン側から世代切り替えと別engineへの再配置を検証する。

CPUとHIPのexpertを同じYAMLに並べ、容量と宣言帯域に基づくロード先選択を実装済み。ローカルCPUの世代切り替え、RX 7900 XTXの出力比較、ConnectX-4 Lxの別ホスト間RoCE v2を検証した。2ソケットのIntel Xeonでも、NIC側のNUMAノードから反対側のCPUとRadeon Pro VII（`gfx906`）へのUPI実行を確認した。MI50そのもの、NFS/RDMAの競合は未検証。

## 成立条件

- 出力がdtypeに応じた許容誤差で参照計算と一致する。
- 切り替え前に受付済みの要求は旧世代で完了する。
- 切り替え後の旧世代要求は明示的に拒否される。
- in-flightの実行と転送が残る領域は解放されない。
- サイズ不正、容量不足、ロード失敗、credit枯渇を明示的に扱う。
- 接続断からの後始末で、使用中バッファを再利用しない。

## 測定する値

token数とhidden dimensionを変えて、演算時間、配送時間、待ち時間、end-to-endのp50/p95/p99、tokens/sを記録する。重みのロード所要時間、入れ替え中の遅延、メモリ使用量も記録する。

測定には機材、NIC、リンク速度、MTU、ソフトウェア版、dtype、重みサイズ、batch条件を添える。ローカル実行との比較で、通信と集約の費用を分離する。

DSparkを追加する段階では、別ソケットのNUMAノードにdrafterを配置し、YAMLで`upi`を選んで動作を確認する。通常decodeと比べ、確定token/s、採択token数と検証token数、経路ごとの要求・応答のバイト数、p99を測る。drafterの往復とターゲット側の検証時間は分けて記録する。

[比較用YAML](../configs/cpu-expert-dspark.example.yml)の3プロファイルでCPU expertの配置と重み、ターゲットモデル、入力を揃える。DSparkを使う2構成は同じdraftモデルと検証設定を使う。単一リクエストと並行リクエストで測り、CPU expertのキュー待ちも記録する。

[処理時間プロファイリング](profiling.md)のメトリクスで構成を比較する。計測の有効・無効でも同じ負荷を流し、確定token/sとp99への計測自体の影響を確認する。

メイン側は1ストリームと2ストリームを同じ配置で比較する。長文ではDSpark継続、DSpark休止後の通常decode、休止後のn-gram先読みを比較し、確定token/s、出力間隔のp99、GPUのピークメモリ、CPU expert待ち、SSDからの再開時間を記録する。

n-gramはリクエスト内だけの場合と、直近リクエストのRAMキャッシュが温まっている場合を比較する。候補の採択数と確定token/sを見て、キャッシュ参照の効果を判断する。expert別カウンタは同じ負荷で有効・無効を比較する。
